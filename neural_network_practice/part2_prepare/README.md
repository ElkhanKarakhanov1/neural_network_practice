# Задание 2. Подготовка данных для нейронной сети

## Назначение модуля

Модуль `part2_prepare` предназначен для поиска файлов данных, преобразования их в числовые массивы, нормализации и сохранения результата в формате NumPy `.npy`. Он поддерживает CSV и изображения. Для управления предусмотрены команды `prepare` и `doctor`, а также интерактивное меню в `main.py`.

Настройки читаются из аргументов командной строки, переменных окружения или значений по умолчанию. Аргументы CLI имеют наивысший приоритет. По умолчанию используются каталоги `data/input` и `data/output` относительно корня проекта.

## 1. Обход дерева каталогов

Поиск реализован в функции `find_files()` модуля `scanner.py` с помощью `os.walk()`. Эта функция последовательно обходит исходный каталог и вложенные папки. Для каждой папки она возвращает её путь, имена подкаталогов и файлов. Поэтому отдельную рекурсивную функцию писать не требуется.

Программа проверяет расширение каждого файла и добавляет подходящие пути в список. Расширения приводятся к нижнему регистру: например, `.CSV` и `.csv` считаются одинаковыми. Имена сортируются, чтобы при неизменном содержимом порядок обработки был воспроизводимым.

Параметр `followlinks=False` запрещает переход по символическим ссылкам на каталоги и помогает избежать циклического обхода. Ошибки доступа передаются обработчику, а отсутствие подходящих файлов сопровождается понятным сообщением.

После поиска CSV читаются как числовые таблицы, а изображения — через Pillow. Таблицы должны иметь одинаковые заголовки и порядок столбцов. CSV и изображения обрабатываются отдельными запусками: без специального правила их нельзя корректно объединить в один числовой массив.

## 2. Нормализация данных

Нормализация приводит признаки к сопоставимому масштабу. Это важно для обучения нейронной сети: если один признак принимает значения от 0 до 1, а другой — до миллиона, оптимизация может стать менее устойчивой и потребовать более осторожного выбора скорости обучения. Масштабирование часто ускоряет сходимость градиентного спуска, но само по себе не гарантирует высокую точность.

### Изображения

Каждое изображение преобразуется в RGB и приводится к одинаковому размеру. Затем формируется массив `float32`, а значения каналов делятся на 255:

```text
x_normalized = x / 255
```

Таким образом, диапазон значений меняется с `[0, 255]` на `[0, 1]`. Результат имеет форму `(N, H, W, 3)`, где `N` — число изображений, `H` и `W` — высота и ширина. Одинаковый размер необходим для объединения изображений в один массив. Простое изменение размера может искажать пропорции, что является ограничением реализации.

### CSV-файлы

Для признаков CSV применяется min-max-нормализация:

```text
x_normalized = (x - min) / (max - min)
```

Минимум и максимум вычисляются отдельно для каждого признака. Если столбец постоянный, знаменатель заменяется на единицу, а результатом становится нулевой столбец. Последний столбец считается целевой переменной и не нормализуется.

Для `dataset.csv` с колонками `x1,x2,label` и бинарными признаками значения остаются прежними: они уже находятся в диапазоне `[0, 1]`.

В текущем сканере параметры min-max рассчитываются по всему объединённому набору. Для независимой оценки модели необходимо сначала выделить train/test, вычислить параметры только на train и затем применить их к test. Параметры следует сохранять для обработки будущих данных. Эти возможности требуют расширения текущей реализации.

## 3. Проблемы больших объёмов данных

Главная опасность — нехватка оперативной памяти, или Out of Memory (OOM). Сейчас сканер накапливает массивы в списке, а затем объединяет их через `np.concatenate()` или `np.stack()`. В момент объединения в памяти одновременно находятся исходные массивы и итоговый результат. Дополнительную память требуют временные массивы при нормализации и преобразовании типов.

Кроме того, размер файлов на диске не равен объёму данных в памяти. Сжатое изображение после декодирования и преобразования в `float32` может занимать значительно больше места. CSV сначала читается в объекты Python, что тоже создаёт накладные расходы.

OOM может привести к `MemoryError`, резкому замедлению из-за использования файла подкачки или принудительному завершению процесса. Отдельно могут возникнуть нехватка места на диске, медленное чтение и недостаток видеопамяти при передаче слишком большого батча на GPU.

## 4. Стратегии обработки частями

### Генераторы и батчи

Вместо загрузки всего набора можно читать ограниченное число строк или изображений и возвращать очередную порцию через `yield`. После обработки батча программа переходит к следующему. Генератор позволяет организовать ленивую выдачу данных, но экономия памяти сохраняется только тогда, когда потребитель не собирает все результаты обратно в список.

Для CSV с глобальной min-max-нормализацией полезны два прохода: сначала вычисляются минимумы и максимумы по обучающим данным, затем каждый батч преобразуется с использованием этих общих параметров. Независимая нормализация каждого батча нежелательна: одинаковые исходные значения могут получить разные преобразования.

### Memory mapping

Для единого большого `.npy` подходит `numpy.lib.format.open_memmap()`. Он позволяет создать массив на диске и заполнять его частями. Форму массива нужно знать заранее, например определить первым проходом.

Готовый файл можно читать с помощью `np.load(path, mmap_mode="r", allow_pickle=False)`, обращаясь к отдельным срезам без предварительной загрузки всего массива. При этом операции, создающие полную копию данных, снова могут вызвать нехватку памяти.

### Dataset и DataLoader

В PyTorch объект `Dataset` может хранить пути к файлам и загружать отдельный пример по запросу. `DataLoader` объединяет примеры в батчи и поддерживает перемешивание и параллельную загрузку. Для потокового чтения подходит `IterableDataset`.

Сам по себе `DataLoader` не решает OOM: если `Dataset` уже загрузил весь набор в конструкторе, память останется занятой. Большое число работников и предварительно загружаемых батчей также увеличивает расход памяти. Поэтому настройку можно начинать с `num_workers=0`, постепенно подбирая параметры. При нескольких работниках `IterableDataset` поток нужно разделять между ними, чтобы избежать повторной выдачи данных.

## 5. Структура и запуск

```text
part2_prepare/
├── app/
│   ├── main.py             # интерактивное меню
│   ├── cli.py              # команды prepare и doctor
│   ├── config.py           # настройки
│   ├── scanner.py          # поиск и преобразование данных
│   └── logging_config.py   # журналирование
└── README.md
```

Зависимости: `numpy`, `Pillow`, `python-dotenv`. TensorFlow и PyTorch не обязательны для текущего сканера.

Команды выполняются из корня репозитория:

```bash
python -m part2_prepare.app.main
python -m part2_prepare.app.cli doctor
python -m part2_prepare.app.cli prepare --path data/input --ext csv --output data/output/prepared.npy
```

Для XOR-файла из четырёх строк и трёх столбцов результат имеет форму `(4, 3)`. Текущий `DatasetManager` первого задания читает CSV: автоматическая загрузка полученного `.npy` в него пока не реализована.

## Заключение

Текущая реализация подходит для небольших учебных наборов: она обеспечивает воспроизводимый поиск, проверку формата и нормализацию. Для больших объёмов нужно сделать потоковым весь конвейер — от чтения до записи или обучения. Генераторы ограничивают число одновременно обрабатываемых примеров, memory mapping позволяет работать с большим массивом на диске, а DataLoader организует подачу батчей нейронной сети.
